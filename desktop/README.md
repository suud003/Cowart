# Yogurt AI desktop bridge

This directory contains a minimal Electron host and a local Codex App Server
sidecar. It intentionally does not change the repository's package scripts or
renderer application.

## Runtime contract

- `main.mjs` loads `YOGURT_VITE_DEV_URL` when it is a loopback HTTP URL;
  otherwise it loads `dist/index.html`.
- `preload.cjs` runs with context isolation, renderer sandboxing, and Node
  integration disabled. It exposes only `window.yogurtAgent`,
  `window.cowartMcp`, and `window.openai.toolOutput`.
- The renderer cannot submit arbitrary App Server RPC methods, shell commands,
  process-spawn requests, MCP server names, or MCP tool names.
- The main process owns `projectDir` and `canvasDir`; renderer-supplied path
  values are overwritten before Cowart MCP calls.

With Electron available, launch the built renderer with:

```powershell
$env:YOGURT_WORKSPACE_ROOT = (Get-Location).Path
npx electron ./desktop/main.mjs
```

For Vite development, set a loopback URL first:

```powershell
$env:YOGURT_VITE_DEV_URL = 'http://127.0.0.1:5173'
npx electron ./desktop/main.mjs
```

## App Server protocol status

The implementation follows the local Codex manual and the schemas generated by
`codex-cli 0.144.3` on 2026-08-25. App Server schemas are version-coupled, so a
packaged desktop release should regenerate or compatibility-test schemas against
its bundled Codex version.

The sidecar launches `codex app-server --listen stdio://` and exchanges one JSON
message per line. It sends `initialize`, waits for the response, emits
`initialized`, and then uses the stable thread/turn, event, approval, model, and
MCP-tool-call methods. WebSocket transport is deliberately unavailable because
the official manual labels it experimental and unsupported. Experimental API
capabilities are also off by default; adding an experimental method requires an
explicit compatibility review.

Renderer events are normalized to these stable names:

- `agent.delta`
- `plan.updated`
- `diff.updated`
- `approval.requested`
- `turn.started`
- `turn.completed`
- `error`
- `state.changed`

`sendTask` resolves when a turn is accepted (or an active turn is steered). Turn
completion is delivered later through `turn.completed`.
